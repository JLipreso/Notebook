# Q-005 — MVP scope & phasing

The brief's Phase 1 has students consuming courses/lessons/quizzes that no teacher can author until Phase 3 (supply-and-demand inversion), and the total MVP spans four products (notebook, LMS, messenger, billing/admin). Where is the cut line?

**Option A — Notebook-first (recommended).** Milestone 1 is purely the notebook core (library, editor, sharing, offline); the classroom layer lands in Milestone 2 together with a minimal teacher authoring portal; money/admin in Milestone 3. See README §3 for the full cut.
- ✅ Ships the differentiator first; no empty-course-module problem; smallest first release.
- ❌ Delays the teacher-led growth loop one milestone.

**Option B — Classroom-first.** Pull minimal teacher authoring (courses, lessons, quizzes, invitations) forward next to the Phase 1 student app; notebook editor ships in parallel or just after.
- ✅ Teacher-led acquisition from day one; reuses the most MIIT knowledge earliest.
- ❌ First release is "another LMS" — the differentiator arrives late; two apps must ship simultaneously.

**Option C — Full brief as phased.** Build Phase 1 exactly as written.
- ❌ Not recommended: students meet empty course modules; messenger + Drive/Calendar + viewers balloon Milestone 1; longest time-to-first-release.

**Decision:** Option A — notebook-first. Locked 2026-09-13 as **D-011** (Lead Developer via option prompt). M1 notebook core → M2 classroom layer with minimal teacher portal → M3 payments + admin, per README §3.
